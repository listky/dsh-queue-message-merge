# DSH 当前会话队列合并器

[English](./README.md) | 简体中文

这是一个用于合并 **当前会话** 中普通排队文本消息的 DSH 插件。它会在聊天输入框旁添加紧凑的图标按钮。合并结果仍保持排队，不会提交或发送消息。

## 设计目的与典型工作流

本插件最初是为配合 [dsbot-session-create](https://github.com/Gaudi-XIX/dsbot-session-create) 的派生会话工作流而设计的。当多个派生会话在相近时间返回结果或回执，并且这些消息已排入当前会话的普通队列时，可以先合并成一条排队消息，再按你原有的工作流转交或发送给主会话，方便主会话集中阅读和处理，而不必逐条处理。

这属于配合使用场景，并非自动集成：本插件不会创建或管理派生会话、跨会话收集消息、将消息路由到主会话，也不会自动发送。它只合并当前会话中符合条件的普通排队文本；何时以及发往何处由你决定。

## 功能

- 按当前会话普通队列 `inbox['next-turn']` 的原有顺序合并。
- 每条消息内部的文本块按原样拼接，消息之间使用英文分号 `;`。
- 先按稳定 ID 编辑首条排队消息，再逐条移除其余消息。成功后只剩一条合并后的排队消息。
- 不读取或修改 steering（`next-step`）和 context 项。
- 输入框旁显示紧凑且可访问的图标按钮。悬停提示显示排队消息数量或不可合并原因；Toast 会显示成功、失败或恢复提示。处于恢复保护状态时，点击按钮只会打开恢复说明，不会启动合并。

## 安装

本仓库提供本地 DSH bundle，目前尚未列入 DSH 插件市场。

1. 克隆或下载本仓库：

   ```sh
   git clone https://github.com/listky/dsh-queue-message-merge.git
   ```

2. 在 DSH 中打开 **Plugins → Add plugin**，选择包含 `package.json` 的克隆目录。
3. 确认 bundle 已启用。替换已经加载的安装版本后，请重启 DSH，以加载新的 Client 模块。

声明支持的 DSH 版本范围为 `>=0.2.2-rc.1 <0.3.0`；插件已在 DSH `0.2.2-rc.1` 上验证。

## 使用

1. 打开要处理的会话。
2. 像平常一样排入至少两条普通、非空的纯文本消息。
3. 悬停合并图标查看消息数量，然后点击。队列不符合条件时，合并操作会禁用；处于恢复保护时，点击按钮只会显示恢复说明，不会启动合并。
4. 成功后 Toast 会提示结果；合并内容仍在队列中。准备提交时，再使用 DSH 原有的发送控件。

普通队列中的每一项都必须符合条件。如果 inbox 投影不可用或格式无效，或任何排队消息缺少/重复 ID、文本为空白、含附件或非文本内容块，插件会拒绝整个合并，不会跳过该项。

## 安全边界与恢复

队列更新通过 DSH 的会话 API 执行。插件不会调用 `prompt` 或 `send`，也不会直接向第三方发起网络请求。DSH 可能为了应用队列编辑而恢复冷会话，但这不会提交排队消息。

当前 Host API 只提供彼此独立的单项队列更新，没有原子批处理、比较并交换或队列锁。插件会在更新之间重新检查投影，但其他窗口或操作者仍可能在检查与请求之间修改队列。因此该操作是尽力而为，不具备并发事务保证。

首次更新前，插件会在 DSH Client store 中写入按会话隔离的恢复标记。标记只保存布尔值，不保存消息正文。成功得到确认或首条编辑被明确拒绝后会清除标记；若请求结果不明确、投影确认超时或后续移除失败，标记会保留，阻止盲目重试。

若进入恢复状态，请先检查当前队列并手动处理部分合并留下的内容，再解除保护。恢复 Toast 提供“我已检查，解除保护”操作；请仅在检查完成后使用。解除标记不会自动修复队列内容。若浏览器存储不可用，标记可能无法在应用重启后保留。

## 开发与测试

需要支持 ES modules 和内置测试运行器的 Node.js。

```sh
npm run build
npm test
npm pack --dry-run
```

修改 `client.source.mjs` 后运行 `npm run build` 重新生成 `client.js`；打包时 `prepack` 也会自动构建。测试使用 fake session/projection 覆盖队列顺序、适用条件、恢复锁、不确定结果和重试拦截，并检查 ModuleLoader 依赖解析与 Toast wiring。这些是单元测试，不是 DSH Host 端到端测试，也不能模拟真实的并发队列修改。
